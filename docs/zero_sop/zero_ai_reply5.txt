# 补全 1：Independent Verifier Protocol

```markdown
---
type: protocol
title: "Zero Independent Verifier Protocol"
file: skills/zero/verifier.sop
max_lines: 100
---

# Independent Verifier Protocol

## Invocation

Main agent calls verifier via subagent at Phase 6.5:

```bash
# Write verification manifest first
python3 $ZERO_TRACKER_PY export-verified $TRACKER \
  > zero_artifacts/verification/manifest.json

# Launch verifier as subagent
# Pass: project path, tracker path (read-only), manifest path
# Verifier has NO write access to tracker — writes to separate file
bash $BOSS_SH "run zero-verifier: \
  project=$PROJECT \
  tracker=$TRACKER \
  manifest=zero_artifacts/verification/manifest.json \
  output=zero_artifacts/verification/result.json \
  timeout=300"
```

## Verifier Agent Instructions

You are an independent verifier. You did not run the sweep.
Your job is to challenge results, not confirm them.

Rules:
1. Read `manifest.json` — this lists every feature marked `verified` with its `reproduce_cmd`
2. Re-run each `reproduce_cmd` exactly as written
3. Record: does re-run produce the same result the main agent claimed?
4. Check 3 random features marked `pass_evidenced` — is the evidence plausible?
5. Write results to `zero_artifacts/verification/result.json`

Do NOT fix anything. Do NOT write to tracker. Read only.

Verification result per item:
```json
{
  "feature_id": "F003",
  "claimed_status": "verified",
  "reproduce_cmd": "npx jest zero_artifacts/batches/batch_01/tests/test_F003.test.ts",
  "verifier_result": "confirmed|disputed|cannot_run",
  "verifier_output_artifact": "zero_artifacts/verification/F003_rerun.txt",
  "dispute_reason": "null or explanation"
}
```

## Timeout and Degraded Mode

```bash
# Verifier has 300 second budget
# If timeout exceeded: mark remaining items as "not_verified_in_time"
# Main agent checks result.json after 300s regardless

# If verifier cannot be launched (no subagent support):
# → Self-verify with explicit caveat
# → Reduce confidence score by flat 15% (unverified penalty)
# → Add to report: "Independent verification unavailable — self-verified"
```

## Main Agent: Process Verifier Results

```bash
# Read verifier output
cat zero_artifacts/verification/result.json

# Count disputes
DISPUTED=$(python3 -c "
import json
r = json.load(open('zero_artifacts/verification/result.json'))
print(sum(1 for x in r if x['verifier_result'] == 'disputed'))
")

# Apply confidence penalty
# Each dispute: -10% confidence
# Each cannot_run: -5% confidence
# Unverified (timeout): -3% per item

# Disputed items → return to Phase 3 batch loop
# cannot_run items → downgrade to 'needs_manual_review'
```

## Concurrent Sweep Safety

```bash
# Check for active sweep lock before starting Phase 0
LOCK_FILE="$PROJECT/.zero_sweep.lock"

if [ -f "$LOCK_FILE" ]; then
  LOCK_PID=$(cat "$LOCK_FILE")
  if kill -0 "$LOCK_PID" 2>/dev/null; then
    echo "ERROR: Another sweep is running (PID $LOCK_PID). Aborting."
    exit 1
  else
    echo "Stale lock found. Previous sweep may have crashed. Removing."
    rm "$LOCK_FILE"
  fi
fi

# Write lock
echo $$ > "$LOCK_FILE"
trap "rm -f $LOCK_FILE" EXIT INT TERM
```

# 补全 2：Controller State Machine (Error Handling)

```markdown
---
type: sop-addition

max_lines: 120
---

# Controller State Machine

Replace the linear sequence in zero_controller.sop with this.

## States

```
INIT → P0_BOOTSTRAP → P1_TRIAGE → P2_INVENTORY → P3_BATCH_LOOP
     → P4_BUSINESS_LOGIC → P5_REGRESSION → P6_CONFIDENCE → COMPLETE

Error states: PHASE_FAILED | ABORTED | SUSPENDED
```

## Transition Rules

```python
TRANSITIONS = {
  "INIT": {
    "on_start": "P0_BOOTSTRAP"
  },
  "P0_BOOTSTRAP": {
    "on_success": "P1_TRIAGE",
    "on_partial": "P1_TRIAGE",        # degraded tools → continue with caveats
    "on_no_tools": "ABORTED",         # zero.sh AND zero_tracker.py both missing
    "on_environment_blocked": "P1_TRIAGE"  # can still triage without test env
  },
  "P1_TRIAGE": {
    "on_success": "P2_INVENTORY",
    "on_no_oracles": "P2_INVENTORY",  # skip triage, continue
    "on_failure": "P2_INVENTORY"      # triage failure is non-fatal
  },
  "P2_INVENTORY": {
    "on_success": "P3_BATCH_LOOP",
    "on_zero_features": "P6_CONFIDENCE",  # nothing to test — still do confidence report
    "on_failure": "ABORTED"           # can't proceed without feature list
  },
  "P3_BATCH_LOOP": {
    "on_batch_complete": "P3_BATCH_LOOP",       # next batch
    "on_all_batches_done": "P4_BUSINESS_LOGIC",
    "on_batch_failure": "P3_BATCH_LOOP",        # log failure, continue next batch
    "on_regression_unresolvable": "P3_BATCH_LOOP",  # mark unresolvable, continue
    "on_context_limit": "SUSPENDED"             # checkpoint and pause
  },
  "P4_BUSINESS_LOGIC": {
    "on_success": "P5_REGRESSION",
    "on_no_applicable_oracles": "P5_REGRESSION",  # skip with note
    "on_failure": "P5_REGRESSION"   # BL audit failure is non-fatal
  },
  "P5_REGRESSION": {
    "on_gate_pass": "P6_CONFIDENCE",
    "on_gate_fail_attempt_1": "P3_BATCH_LOOP",  # return to fix regressions
    "on_gate_fail_attempt_2": "P3_BATCH_LOOP",
    "on_gate_fail_attempt_3": "P6_CONFIDENCE",  # give up, report unresolved
    "on_environment_blocked": "P6_CONFIDENCE"
  },
  "P6_CONFIDENCE": {
    "on_verifier_disputes": "P3_BATCH_LOOP",  # fix disputed items
    "on_verifier_complete": "COMPLETE",
    "on_verifier_unavailable": "COMPLETE"     # with degraded confidence
  },
  "SUSPENDED": {
    "on_resume": "<last_active_phase>"        # read from tracker
  }
}
```

## Phase Invocation Template

```bash
invoke_phase() {
  local PHASE=$1
  local SOP_FILE="skills/zero/phases/p${PHASE}.sop"
  
  # Load phase SOP
  echo "=== LOADING PHASE $PHASE ==="
  cat "$SOP_FILE"
  
  # Execute (agent processes the loaded SOP)
  # ... agent execution ...
  
  # Write checkpoint
  bash $ZERO_SH --log $PROJECT "{
    \"phase\": $PHASE,
    \"action\": \"phase_complete\",
    \"timestamp\": \"$(date -u +%Y-%m-%dT%H:%M:%SZ)\",
    \"next_state\": \"$NEXT_STATE\"
  }"
  
  # Unload (agent must not carry phase content forward)
  echo "=== UNLOADING PHASE $PHASE ==="
}
```

## Abort Conditions (non-negotiable)

Abort and halt sweep if:
1. `zero.sh` AND `zero_tracker.py` both missing (cannot checkpoint anything)
2. Project path does not exist or is not readable
3. Concurrent sweep lock held by live process
4. User sends `/zero --abort` command

On abort:
```bash
bash $ZERO_SH --log $PROJECT '{"action": "sweep_aborted", "reason": "..."}'
rm -f "$PROJECT/.zero_sweep.lock"
# Report partial results if any exist
bash $ZERO_SH --report $PROJECT 2>/dev/null || true
```

## Suspension (context limit recovery)

When approaching context limit mid-phase:
```bash
# 1. Write current state
bash $ZERO_SH --log $PROJECT "{
  \"action\": \"suspended\",
  \"phase\": $CURRENT_PHASE,
  \"batch\": \"$CURRENT_BATCH\",
  \"features_remaining\": $REMAINING,
  \"resume_instruction\": \"Load p${CURRENT_PHASE}.sop, read tracker, continue from batch $NEXT_BATCH\"
}"

# 2. Notify user
echo "SWEEP SUSPENDED: Context limit approaching."
echo "Phase $CURRENT_PHASE, batch $CURRENT_BATCH complete."
echo "Processed $PROCESSED/$TOTAL features."
echo "Resume with: /zero --resume $PROJECT"
```

## Cancellation

```bash
# /zero --abort $PROJECT
bash $ZERO_SH --log $PROJECT '{"action":"user_abort","partial_results":"see tracker"}'
rm -f "$PROJECT/.zero_sweep.lock"
echo "Sweep cancelled. Partial results in zero_tracker.jsonl"
```

  "framework": "express",
  "oracle": "triage/cwe862",

  "action": "trace_required_before_confirm"
}'

# General lesson (syncs to global)
bash $ZERO_SH --lessons $PROJECT '{
  "category": "general",
  "stack": "any",
  "oracle": "business_logic/financial",
  "lesson": "parseFloat in monetary context = real bug, not FP",
  "false_positive_rate": "low",
  "signal_quality": "high",
  "action": "confirm_immediately_on_hit"
}'
```

## Injecting Lessons (Phase 0)

```bash
# Load lessons relevant to current stack + framework
STACK="nodejs"
FRAMEWORK="express"

python3 -c "
import json, sys
from datetime import datetime, timedelta

lessons = []
with open('memory/zero_lessons.jsonl') as f:
    for line in f:
        l = json.loads(line)
        # Skip stale
        created = datetime.fromisoformat(l['created'])
        expires = l.get('expires_after_days', 180)
        if (datetime.now() - created).days > expires:
            continue
        # Match stack/framework
        if l['stack'] not in ['$STACK', 'any']:
            continue
        if 'framework' in l and l['framework'] not in ['$FRAMEWORK', 'any']:
            continue
        lessons.append(l)

# Sort by signal_quality DESC, confirmation_count DESC
lessons.sort(key=lambda x: (
    {'high':3,'medium':2,'low':1}.get(x.get('signal_quality','low'), 1),
    x.get('confirmation_count', 1)
), reverse=True)

# Return top 20
for l in lessons[:20]:
    print(json.dumps(l))
" 2>/dev/null
```

## Pruning (run at end of each sweep)

```bash
python3 -c "
import json
from datetime import datetime

output = []
with open('memory/zero_lessons.jsonl') as f:
    for line in f:
        l = json.loads(line)
        created = datetime.fromisoformat(l['created'])
        expires = l.get('expires_after_days', 180)
        age_days = (datetime.now() - created).days
        
        # Keep if: not expired
        if age_days <= expires:
            output.append(l)
            continue
        
        # Keep if: high confirmation count (proven, keep longer)
        if l.get('confirmation_count', 1) >= 5:
            l['expires_after_days'] = expires + 180  # extend
            output.append(l)
            continue
        
        # Prune: expired + low confirmation
        print(f'PRUNED: {l[\"id\"]} — {l[\"lesson\"][:50]}', file=__import__('sys').stderr)

with open('memory/zero_lessons.jsonl', 'w') as f:
    for l in output:
        f.write(json.dumps(l) + '\n')

print(f'Lessons after pruning: {len(output)}')
" 2>/dev/null
```

## Conflict Resolution

If two lessons contradict each other for the same oracle:
```python
# Rule: higher confirmation_count wins
# If equal: more recent wins
# If same day: keep both, flag as "conflicting"

# Conflicting lesson flag
{
  "conflicting_with": "L003",
  "conflict_note": "L001 says high FP rate, L003 says low FP. Resolved by count."
}
```

## Staleness Detection

A lesson is stale if ANY of:
- Age > `expires_after_days` (default 180)
- Referenced oracle file no longer exists
- Stack/framework version changed significantly (manual flag)

```bash
# Check for orphaned oracle references
python3 -c "
import json, os

    for line in f:
        l = json.loads(line)
        oracle = l.get('oracle', '')
        oracle_path = f'skills/zero/oracles/{oracle}.oracle'
        if oracle and not os.path.exists(oracle_path):
            print(f'STALE ORACLE REF: {l[\"id\"]} → {oracle_path}')
" 2>/dev/null

## Discovery

```bash
# Find check-then-act patterns
grep -rn $INCLUDE $EXCLUDE \
  -e "findOne.*then.*save\|findById.*then.*update" \
  -e "if.*count.*==.*0.*create\|if.*exists.*return" \
  $PROJECT 2>/dev/null \
  | grep -v "test\|spec" \
  | tee zero_artifacts/business_logic/check_then_act.txt

# Find missing unique constraints (likely duplicate creation risk)
grep -rn $INCLUDE $EXCLUDE \
  -e "unique.*:\|UNIQUE\|unique_together\|@Unique\|@Index.*unique" \
  $PROJECT 2>/dev/null \
  | tee zero_artifacts/business_logic/unique_constraints.txt

# Find queue/job processing
grep -rn $INCLUDE $EXCLUDE \
  -e "Queue\|Bull\|BullMQ\|Celery\|Sidekiq\|RQ\|NATS\|Kafka" \
  $PROJECT 2>/dev/null \
  | tee zero_artifacts/business_logic/queues.txt

# Find optimistic locking (good — means they thought about concurrency)
grep -rn $INCLUDE $EXCLUDE \
  -e "version\|@Version\|optimistic\|cas\|compare.*and.*swap" \
  $PROJECT 2>/dev/null \
  | tee zero_artifacts/business_logic/optimistic_locking.txt
```

## Checks

| ID | Check | Evidence needed |
|----|-------|----------------|
| CONC-01 | No check-then-act on shared resources without lock | grep hit + trace showing no transaction/lock |
| CONC-02 | Unique constraints exist for uniqueness-critical fields | Model has unique constraint on email/username/etc |
| CONC-03 | Queue jobs are idempotent | Job handler can process same message twice safely |
| CONC-04 | Payment/debit operations have idempotency key | Idempotency key passed to payment provider |
| CONC-05 | Database constraints enforce uniqueness (not just app-level) | DB migration has UNIQUE INDEX |

## Test Template

```typescript
// CONC-01: Concurrent creation race condition
it('CONC-01: concurrent requests create only one resource', async () => {
  const uniqueEmail = `test-${Date.now()}@example.com`
  
  // Fire N simultaneous requests
  const requests = Array(5).fill(null).map(() =>
    request(app)
      .post('/api/users')
      .send({ email: uniqueEmail, password: 'password123' })
  )
  
  const results = await Promise.all(requests)
  
  const successes = results.filter(r => r.status === 201)
  const conflicts = results.filter(r => r.status === 409)
  
  // Exactly one should succeed
  expect(successes.length).toBe(1)
  // Others should get appropriate error
  expect(conflicts.length).toBe(4)
  
  // Verify only one user exists in DB
  const users = await getUsersByEmail(uniqueEmail)
  expect(users.length).toBe(1)
})
```

## Important Caveat

Race condition tests are probabilistic. A passing test does NOT guarantee no race condition.
If CONC-01 patterns found in code but test passes → note as `suspected_concurrent_risk`.
Recommend DB-level unique constraint as defense-in-depth regardless of test result.

# Confidence Score: What to Do With It

## Threshold Table

| Score | Rating | Action |
|-------|--------|--------|
| ≥ 85% | High confidence | Report as complete. Recommend: commit generated tests, add CI gates. |
| 70-84% | Medium-high | Report as substantially complete. List `low` and `none` coverage gaps explicitly. Recommend: follow-up manual review on gaps. |
| 55-69% | Medium | Report as partial. Mandatory: list all uncovered high-risk features by name. Recommend: second sweep scoped to gaps. |
| 40-54% | Low | Report as preliminary. Mandatory: do NOT mark sweep as "passed". Recommend: environment setup + second full sweep. |
| < 40% | Very low | Report as incomplete. Mandatory: stop. Do not report bugs as "fixed" — can't verify. Provide gap report only. |

## Risk-Adjusted Thresholds

For projects with `payment_operation` or `admin_action` features:
- Minimum acceptable threshold is 75% (not 55%)
- Any payment or admin feature with `low` or `none` coverage → automatic flag
- Report cannot be marked complete until those specific features reach `medium` minimum

## Threshold Violation Response

If score is below threshold for project type:
```bash
bash $ZERO_SH --log $PROJECT '{

  "threshold": M,
  "high_risk_uncovered": ["F003", "F007"],
  "recommendation": "second_sweep|environment_fix|manual_review"
}'
```

# Generated Test Lifecycle

## Sweep Start: Clean Artifacts

```bash
# At Phase 0 init, before any work:
if [ -d "$PROJECT/zero_artifacts" ]; then
  # Keep baseline files (they're from before this sweep)
  # Remove previous batch/test artifacts
  find "$PROJECT/zero_artifacts" -name "*.txt" -not -name "baseline_*" -delete
  find "$PROJECT/zero_artifacts" -name "*.test.*" -delete
  find "$PROJECT/zero_artifacts" -name "*.result.txt" -delete
  echo "Cleaned previous sweep artifacts"
fi
```

## Test Deduplication

Before generating a test, check if equivalent exists:

```bash
# Check if a test for this feature + behavior already exists
grep -rn "F${FEATURE_ID}\|${BEHAVIOR_ID}" \
  "$PROJECT/src/__tests__/zero_generated/" 2>/dev/null | head -5
```

If found → do not regenerate. Re-run existing test instead.

## Test Commit Decision (Phase 5)

A generated test should be committed if ALL:
- It found a real confirmed bug (`evidence_type = generated_test_fail`)
- The bug was fixed and verified
- The test is not already covered by existing test suite
- The test is self-contained (no zero_artifacts dependencies)

A generated test should NOT be committed if:
- It only passed (no bug found — might just test happy path we already know works)
- It depends on zero_artifacts paths or test utilities
- It duplicates an existing test
- It's a concurrency test that's probabilistic (commit with strong caveat comment)

```bash
# Commit worthy tests
mkdir -p "$PROJECT/src/__tests__/zero_generated"

for test in zero_artifacts/batches/*/tests/*.test.ts; do
  FEATURE_ID=$(basename "$test" | grep -o 'F[0-9]*')
  
  # Check if this test found a real bug
  FOUND_BUG=$(python3 $ZERO_TRACKER_PY query $TRACKER \
    "feature_id=$FEATURE_ID AND evidence_type=generated_test_fail" 2>/dev/null)
  
  if [ -n "$FOUND_BUG" ]; then
    # Add header comment
    echo "// Generated by Zero Sweep $(date +%Y-%m-%d). Found real bug in F${FEATURE_ID}." \
      > "$PROJECT/src/__tests__/zero_generated/${FEATURE_ID}_$(basename $test)"
    cat "$test" >> "$PROJECT/src/__tests__/zero_generated/${FEATURE_ID}_$(basename $test)"
    echo "COMMITTED: $test → zero_generated/"
  fi
done
```

## Stale Test Detection (future sweeps)

At Phase 0, check committed zero_generated tests against current code:
```bash
# Find zero_generated tests whose feature code has changed since test was written
for test in "$PROJECT/src/__tests__/zero_generated/"*.test.ts; do
  FEATURE_ID=$(grep -o 'F[0-9]*' "$test" | head -1)
  CODE_FILE=$(python3 $ZERO_TRACKER_PY get $TRACKER $FEATURE_ID code_location 2>/dev/null)
  
  if [ -n "$CODE_FILE" ]; then
    TEST_DATE=$(git log --format="%ai" -- "$test" | head -1)
    CODE_CHANGED=$(git log --after="$TEST_DATE" --format="%ai" -- "$CODE_FILE" | head -1)
    
    if [ -n "$CODE_CHANGED" ]; then
      echo "STALE TEST: $test — code changed after test was written"
      echo "Review: does test still reflect intended behavior?"
    fi
  fi
done
```
