# zero_controller.sop

```markdown
---
type: sop
title: "Zero Controller"
version: 4
max_lines: 200
load_policy: always
---

# Zero Controller

You orchestrate a quality sweep. You do NOT execute phases directly.
You load the correct phase SOP, execute it, checkpoint, then load the next.

One phase SOP in context at a time. Unload before loading next.

## Non-Negotiable Rules

1. No PASS without objective evidence (tool output / test result)
2. No confirmed BUG without reproduction (failing test / traced data flow / static finding)
3. Suspected = grep hit not yet traced. Must trace before confirming or clearing.
4. Never hold sweep state in context only — write to tracker after every action
5. Final verification must be run by a separate agent instance (not self)
6. Confidence score must include explicit gap statement

## Execution Sequence

```
Phase 0: Bootstrap
  → Load p0_bootstrap.sop
  → Execute fully
  → Write repo_facts + baseline to tracker
  → Unload p0_bootstrap.sop

Phase 1: Triage
  → Load p1_triage.sop + relevant oracles/triage/*.oracle
  → Execute fully  
  → Write all suspected_issues to tracker
  → Unload

Phase 2: Feature Inventory
  → Load p2_inventory.sop
  → Execute fully
  → Write all feature records + oracle assignments to tracker
  → Decide mode (call boss.sh or apply heuristic)
  → Unload

Phase 3: Batch Loop (repeat until all batches done)
  → Load p3_batch_loop.sop + relevant oracle files for this batch
  → Execute one batch
  → Write all results to tracker
  → Unload
  → Next batch

Phase 4: Business Logic Audit
  → Load p4_business_logic.sop + relevant business_logic/*.oracle
  → Execute per subsystem
  → Write findings to tracker
  → Unload

Phase 5: Regression Gate
  → Load p5_regression.sop
  → Execute
  → Write final test results to tracker
  → Unload

Phase 6: Confidence + Verification
  → Load p6_confidence.sop
  → Compute confidence score
  → Launch SEPARATE AGENT for independent verification
  → Write final report
  → Sync lessons
```

## Mode Decision (after Phase 2)

Call boss.sh:
```bash
bash $BOSS_SH "zero audit: files=$FILE_COUNT features=$FEATURE_COUNT \
  stack=$STACK tests_exist=$TEST_COUNT mode=evidence-driven"
```

Fallback if boss unavailable:
- ≤15 features: direct
- 16-50 features: conductor  
- >50 features: conductor + hive
- Long unattended run: add goal

## Checkpoint Format (write after every phase)

```bash
bash $ZERO_SH --log $PROJECT '{"phase": N, "action": "phase_complete", 
  "features_processed": N, "issues_found": N, "time_elapsed": "Xm"}'
```

## Context Budget Management

If context is approaching limit mid-phase:
1. Write current state to tracker immediately
2. Output: "CHECKPOINT: Phase N, batch M complete. Resuming in next context."
3. On resume: read tracker to reconstruct state, continue from checkpoint

## Lessons Injection (Phase 0 reads this)

Before starting any phase, inject relevant lessons:
```bash
# Load lessons relevant to this project's stack
grep "$STACK\|general" memory/zero_lessons.jsonl | tail -20
```

Use lessons to:
- Skip known false positive patterns
- Prioritize oracle checks that have historically found bugs
- Adjust confidence weights for known unreliable oracles
```

# Phase 3: Batch Execution

Input: batch_id, list of feature_ids, their oracle_plans, their suspected_issues

## 3.1 Confirm or Clear Triage Hits

For every suspected_issue linked to this batch's features:

```bash
# Trace data flow: does user input reach the flagged sink?
codegraph_callers "<flagged_function>" 2>/dev/null

# Fallback: manual trace
# Open flagged file:line
# Answer: where does the input come from?
#   - req.body / req.params / req.query / req.headers → CONFIRMED (user-controlled)
#   - internal function / trusted service → CLEAR (false positive)
#   - config / env var → depends (clear if not user-controlled)
```

Update tracker immediately:
- Confirmed: change status from `suspected` to `confirmed`, add `taint_path`
- Cleared: change status to `false_positive`, add reason

```bash
bash $ZERO_SH --lessons $PROJECT '{
  "category": "project",
  "lesson": "Pattern X at location Y is false positive because Z"
}'
```

## 3.2 Run Existing Tests for This Batch

```bash
# Scope to this batch's subsystem
npm test -- --testPathPattern="<subsystem>" 2>&1 \
  | tee zero_artifacts/batches/$BATCH_ID/existing_tests.txt

# Python
pytest tests/<subsystem>/ -v 2>&1 \
  | tee zero_artifacts/batches/$BATCH_ID/existing_tests.txt
```

Record which features have existing test coverage.
Mark features without coverage as `needs_generated_test`.

## 3.3 Generate Tests for Uncovered Features

Load the template from `oracles/test_templates/<template>.tmpl` for each feature.

**Critical rules for test generation:**
- Tests must be self-contained (no dependency on other generated tests)
- Tests must be runnable with the project's existing test framework
- Tests must have concrete assertions (not `expect(result).toBeTruthy()`)
- Each test must target exactly ONE behavior from expected_behavior

Minimum tests to generate per feature based on oracle plan:
- auth_bypass.tmpl → generates: no-token test, wrong-token test, expired-token test, wrong-role test
- idor.tmpl → generates: cross-user access test, cross-user modify test, cross-user delete test  
- financial.tmpl → generates: concurrent-charge test, over-refund test, negative-amount test
- state_machine.tmpl → generates: invalid-transition test, terminal-state test, concurrent-transition test

```bash
# Save generated test
cat > zero_artifacts/batches/$BATCH_ID/tests/test_$FEATURE_ID.test.ts << 'TESTEOF'
<generated test code>
TESTEOF

# Run it immediately
npx jest zero_artifacts/batches/$BATCH_ID/tests/test_$FEATURE_ID.test.ts \
  2>&1 | tee zero_artifacts/batches/$BATCH_ID/tests/test_$FEATURE_ID.result.txt
echo "EXIT:$?"
```

## 3.4 Record Confirmed Bugs

Only record as `confirmed` if:
- existing test fails (exit code non-zero, FAIL in output)
- generated test fails (assertion failure, not setup error)
- static tool finding (from Phase 1 triage, now trace-confirmed)
- runtime repro command demonstrates incorrect behavior

A setup error (can't connect to DB, missing env) is NOT a bug confirmation.

Required fields per confirmed bug:
```json
{
  "issue_id": "I-014",
  "feature_id": "F003",
  "category": "security|business_logic|code_quality|config",
  "severity": "critical|high|medium|low",
  "confidence": "confirmed",
  "title": "...",
  "expected": "...",
  "actual": "...",
  "evidence_type": "existing_test_fail|generated_test_fail|static_finding|trace_confirmed",
  "evidence_artifact": "zero_artifacts/batches/...",
  "reproduce_cmd": "exact command",
  "taint_path": "req.body.X → func Y → sink Z (no check)",
  "location": "file:line"
}
```

## 3.5 Fix Confirmed Issues

Before any fix:
```bash
codegraph_impact "<function_to_change>" 2>/dev/null \
  | tee zero_artifacts/batches/$BATCH_ID/impact_$ISSUE_ID.txt
```

Record all impacted features. Flag them for regression.

Fix rules:
- Minimum change only
- No refactoring
- No opportunistic improvements
- New bugs found while fixing → add to tracker, fix after this batch completes

## 3.6 Verify Fix (Mandatory)

```bash
# Re-run the exact failing command/test
<reproduce_cmd from bug record>

# Re-run ALL tests in this batch (not just impacted — fixing shared code can affect anything)
npm test -- --testPathPattern="<subsystem>" 2>&1 \
  | tee zero_artifacts/batches/$BATCH_ID/post_fix_tests.txt

# Re-run impacted feature tests
for feature in <impacted_features>:
  npm test -- --testPathPattern="<feature_pattern>"
```

Status outcomes:
- `verified`: original failing oracle now passes, no new failures in batch
- `fix_failed`: original oracle still fails
- `regressed`: new test failures appeared that weren't there before fix

If `regressed`: add regression as confirmed bug, include `caused_by: <issue_id>`.
Fix regressions before moving to next batch.

## 3.7 Feature Final Status Update

```bash
python3 $ZERO_TRACKER_PY update $TRACKER $FEATURE_ID \
  status <pass_evidenced|verified|fail_confirmed|blocked_environment|needs_oracle> \
  evidence_type <type> \
  evidence_artifact <path>
```

- [ ] All features: have oracle result recorded
- [ ] All confirmed bugs: have evidence_artifact path
- [ ] All fixes: verified with re-run of original failing oracle
- [ ] All regressions: resolved before batch marked complete
- [ ] All feature statuses: updated in tracker
- [ ] Impact of fixes: recorded (for Phase 5 regression scope)

# Phase 5: Regression Gate

## Purpose

Verify the sweep did not degrade baseline quality.
Every fix in Phase 3-4 must leave the project in better or equal state.

## 5.1 Re-run Full Test Suite

```bash
cd $PROJECT
npm test 2>&1 | tee zero_artifacts/final_test.txt; echo "EXIT:$?"
npx tsc --noEmit 2>&1 | tee zero_artifacts/final_typecheck.txt; echo "EXIT:$?"
npx eslint . --max-warnings=9999 2>&1 | tee zero_artifacts/final_lint.txt
npm audit --json 2>&1 | tee zero_artifacts/final_audit.txt
```

## 5.2 Compare Against Baseline

```bash
# Test delta
BASELINE_PASS=$(grep -c "PASS\|passed\|ok" zero_artifacts/baseline_test.txt || echo 0)
FINAL_PASS=$(grep -c "PASS\|passed\|ok" zero_artifacts/final_test.txt || echo 0)
BASELINE_FAIL=$(grep -c "FAIL\|failed" zero_artifacts/baseline_test.txt || echo 0)
FINAL_FAIL=$(grep -c "FAIL\|failed" zero_artifacts/final_test.txt || echo 0)

echo "Tests: $BASELINE_PASS → $FINAL_PASS passing"
echo "Failures: $BASELINE_FAIL → $FINAL_FAIL failing"

# Typecheck delta
BASELINE_TC=$(wc -l < zero_artifacts/baseline_typecheck.txt)
FINAL_TC=$(wc -l < zero_artifacts/final_typecheck.txt)
echo "Typecheck lines: $BASELINE_TC → $FINAL_TC"
```

## 5.3 Gate Rules

**PASS gate (all must hold):**
- `FINAL_FAIL ≤ BASELINE_FAIL` — did not introduce new test failures
- `FINAL_TC ≤ BASELINE_TC + 5` — did not introduce significant new typecheck errors
- New lint errors ≤ 0 relative to baseline

**If gate fails:**
- Identify which tests newly failed (diff outputs)
- Match to recent fixes in Phase 3-4 tracker records
- Return to batch loop for those features only
- Re-verify after fix
- Max 3 regression iterations before marking as `unresolvable`

## 5.4 Identify Tests to Commit

Generated tests that:
- Found a real bug (evidence_type = generated_test_fail + verified)
- Are now passing after fix
- Have concrete assertions

→ These should be committed to the repo's actual test suite (not just zero_artifacts)

```bash
# Move worthy generated tests to project test directory
cp zero_artifacts/batches/*/tests/test_*.test.ts $PROJECT/src/__tests__/zero_generated/
```

## Phase 5 Exit Criteria
- [ ] Full test suite re-run completed
- [ ] Baseline comparison computed
- [ ] Gate rules evaluated
- [ ] Regression failures resolved or marked unresolvable
- [ ] Tests to commit identified
