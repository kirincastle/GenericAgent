## Proxy Health Enhancement (2026-06-17)
- Bad proxy detection: connection timeout/SOCKS5 error → mark bad, no need 429
- 429 triggers rotation to next alive proxy (not just rate-limit config)
- 50%+ bad → 触发 xray 订阅刷新（宿主机 `/root/xray-proxy/sync-sub.py`，非 container 内 subscription 命令）
- Recently-429'd alive proxies can be rotated back
- Subscription refresh **always** runs before cooldown check (every `rotateXrayProxy()` call regardless of cooldown), compiled into binary, persists across upgrades
- Bugfix: was after cooldown check — high 429 frequency hit cooldown, skipped refresh
- **Gotcha**: 429 count is per-node (in-memory), NOT per-proxy. Same proxy pool shared by v3/v6 can show 429 on one node but healthy on another.
- **429 auto-recovery** (v3.013+): `proxy429RecoveryCount` counter, reset on new 429, clear after 3 consecutive healthy probes. Commit `817eb0c`
- Code: opencode2api.go, deployed v3.009→v3.015
